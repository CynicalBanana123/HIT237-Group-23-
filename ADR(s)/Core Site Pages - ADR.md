# Core Functionality

## 31/03/2026 Revision:

### Status:
Approved

### Context
The application must have multiple pages to serve its function as a ticket system for repair requests.

### Alternative Solutions Considered
1. Account and settings page
  - Pros
    - Some extra accessibility options
  - Cons
    - Accessibility features would need to be added to an already bare site.
2.	Account Page
  - Pros
    - Ability to update details if necessary
  - Cons
    - Accounts are assumed to be shared with MyGov, so conflicts would need to be avoided.

### Solution Decided Upon:
The following pages were decided upon; A login page for attributable information. A ticket page unique to individual accounts, so that current and prior tickets can be seen and from which new tickets can be created. A ticket creation page so that clients can submit requests for services. Additionally, an admin page in which ticket requests can be easily tracked and acted upon.

### Consequences:
The site will have limited accessibility tools or customisability, as it will focus on bare functionality as a repair/maintenance request service.
